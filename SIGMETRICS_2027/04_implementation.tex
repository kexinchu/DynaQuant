\section{Implementation}
\label{sec:impl}

We implement \systemname\ in Python using PyTorch and HuggingFace
Transformers~\cite{paszke2019pytorch,wolf2020transformers}.  The CPU decision
plane evaluates byte exchanges, while the device-memory path owns
representation storage, publication, and reclamation.

\paragraph{Controller.}
A predicted use records its expert, representation tier, issue layer, and use
layer.  The implemented predictor ranks experts from recent layer-local
activation counts and limits its output to a configured width.  Replay uses
measured layer time and copy bandwidth to simulate one migration queue and
compute readiness and exposed wait from CPU-side placement metadata.  At each
routed layer, one admission path forms lookahead candidates and updates the
adaptive candidate envelope from observed stall and pollution.  A slower
interval on that same path refreshes fidelity requests.  Fidelity tenure and replacement
hysteresis are stored with their byte leases.

\paragraph{Representations.}
Both representation tiers are prepared in pinned host memory before a timed
run.  Packing proceeds one layer at a time and releases that layer's source
weights after both tiers are complete.  The tier pair is fixed for a
checkpoint and does not change with \(B\).  Format metadata is published with
the representation, and a layer containing both tiers issues one grouped GEMM
per tier.  A startup probe measures the largest conversion workspace; the
runtime reserves it before allocating expert memory.

\paragraph{Arena and exchange execution.}
The shared expert arena stores every device-resident expert representation without
layer, tier, or lease-purpose partitions.  The arena may contain multiple
preallocated segments.  The allocator rounds requests to 256-byte alignment,
selects the smallest compatible free extent, splits it, and coalesces adjacent
free ranges within the same segment.

The memory manager holds named donors and binds all destination extents under
one mutex.  If any binding fails, it releases every new extent and donor hold
before returning.  It distinguishes insufficient aggregate bytes from the
absence of a compatible extent.  A bounded worker queue applies backpressure
before reservation, and donor holds prevent concurrent exchanges from
spending the same future release.

Accepted copies run on a dedicated CUDA stream.  A worker writes the packed
representation and any kernel-native layout into the reserved extent, then
waits for the completion event before publication.  Copy or publication
failure rolls back a destination that never became visible.

\paragraph{Publication and dispatch.}
A published handle contains the tier, arena extent, format metadata, and a
monotonically increasing version.  The forward path acquires a reader
reference before resolving the extent and releases it after kernel launch,
recording the latest completion event for each compute stream.  Publication
atomically replaces the registry entry.  Reclamation waits for the old
handle's readers and recorded events; without a precise event, it uses a
conservative device synchronization.  This sequence closes the race between
pointer lookup, kernel launch, and extent reuse.

The dispatcher launches groups backed by published representations before a
group waiting on a transfer.  Repeated uses of one destination share its copy
and readiness event.  The runtime logs arena occupancy, reservation failures,
and exchange decisions.  On NVIDIA systems, a separate monitor samples
process memory through NVML every 2\,ms.  A run is invalid if published plus
reserved arena bytes exceed \(B\).
