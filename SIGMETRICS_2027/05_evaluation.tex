\section{Evaluation}
\label{sec:eval}

We evaluate five questions.  RQ1 asks whether \systemname\ improves tail
latency at the same expert-memory budget and quality-degradation limit.  RQ2
tests whether joint online allocation is necessary.  RQ3 attributes the result
to counterfactual valuation, explicit donors, and the shared expert arena.
RQ4 measures model accuracy and runtime cost.  RQ5 identifies operating
regions in which a simpler policy is sufficient.

\subsection{Experimental Setup}
\label{sec:eval-setup}

\paragraph{Platform and models.}
The primary platform is one NVIDIA RTX A6000 with 48\,GB of device memory.
Table~\ref{tab:eval-models} reports the exact checkpoint revision, packed
representation pair, measured expert footprints, and tested values of the
expert-memory budget \(B\).  A checkpoint enters the study only after both
representations pass the kernel-correctness tests.  Non-expert parameters, KV
cache, activations, conversion workspace, and a safety margin are reserved
before the shared expert arena is created.  Across these runs, \(B\) is
the expert-memory axis.  Host-to-device bandwidth is the measured copy rate
on that platform, and the controlled copy-rate limit swept in
Section~\ref{sec:eval-robustness}.  These two axes are the two budgets posed
in Section~\ref{sec:intro}.

\paragraph{Workloads and quality.}
Latency requests use length-stratified ShareGPT
traces~\cite{ShareGPT_Vicuna_unfiltered}, including prefill-heavy,
decode-heavy, and balanced-length slices.  We measure the isolated model path;
request queueing, tokenization, transport, and serialization are outside the
timed region.  Quality is measured with WikiText-2
perplexity~\cite{merity2016pointer} and \tbd{validated downstream tasks}.
Calibration prompts determine sensitivity values, predictor width, controller
constants, and baseline settings.  Test prompts are disjoint, and no constant
is refit on them.  We report each quality task separately against the all-high
reference.  The reference uses FP16 for every executed expert in the same
runtime and streams absent experts through the same residency path.  Thus
``all-high'' fixes fidelity, not placement, and does not assume that every
FP16 expert fits in HBM simultaneously.

\paragraph{Baselines.}
Table~\ref{tab:eval-baselines} groups policies by capability.  Uniform-low,
Static-mixed, Residency-only, and Lookahead-only isolate one memory use.
\textsc{Seq-FR} assigns fidelity
before residency and lookahead; \textsc{Seq-RF} reverses the order.
\textsc{Static-Joint} searches all three byte shares on calibration data and
freezes the best feasible point.  Fixed-partition tunes three private quotas.
A deployable baseline receives the same calibration traces and search budget
as \systemname.
A comparison is reportable only when all deployable policies receive the same
\(B\), representations, kernels, request stream, and transition interface.
Matched implementations of HOBBIT and DyMoE are marked HOBBIT-M and DyMoE-M
and are included only after their behavior is validated on the same
checkpoint~\cite{tang2024hobbit,huang2026dymoe}.  Test-side grid search and
offline exchange optimization are reported only as upper bounds.

\paragraph{Metrics and statistics.}
The primary endpoint is p95 time per output token (TPOT) subject to
\(\Delta Q\leq\epsilon\).  We also report p99 TPOT, p95 time to first token
(TTFT), SLO attainment, exposed wait, migration bytes, and eviction-induced
reload bytes.  Every configuration uses five warm-up iterations and 100
measured requests for each of five paired seeds.  Policies receive identical
request orders.  Tail-latency differences use a paired bootstrap clustered by
seed and request trace.  We report 95\% confidence intervals, the per-seed
values, and the median and range across seeds.  Accuracy uses Wilson intervals;
paired binary outcomes use McNemar's test, and nonbinary task metrics use a
paired item bootstrap.  Perplexity intervals are bootstrapped over token
windows.  The primary comparison is \systemname\ against the strongest
deployable baseline.  Secondary comparisons use Holm correction.  Overlapping
intervals are reported as inconclusive, and scores from different quality
tasks are never pooled.

\paragraph{Memory accounting and admission.}
Each run records published plus reserved arena bytes and process memory sampled
through NVML every 2\,ms.  A run is invalid if arena occupancy exceeds \(B\),
if the quality-degradation limit is violated, or if its exchange log cannot
reconstruct the reported allocation.  Process memory is reported separately
because it contains non-expert state.  External fragmentation is

\begin{equation}
  F_{\mathrm{ext}} = 1 -
  \frac{\text{largest free extent}}{\text{total free arena bytes}}.
  \label{eq:external-fragmentation}
\end{equation}

We distinguish failures caused by insufficient aggregate bytes from failures
caused by the absence of a compatible extent.  The artifact also records the
checkpoint revision, packing recipe, controller constants, allocator
alignment, random seed, and concurrent device processes.

\subsection{Mechanism Attribution}
\label{sec:eval-mechanism}

\paragraph{RQ3: Which mechanisms account for the result?}
We replace one mechanism at a time while holding the workload, \(B\), and data
path fixed.  Independent-value scores requests without counterfactual replay.
Slack-only admission removes explicit donors.  Fixed-partition replaces byte
exchange with three tuned private quotas.  Single-timescale merges the fast
and slow updates, while No-tenure removes fidelity tenure and replacement
hysteresis.  A fixed-arena-partition variant isolates the allocator from the
allocation policy.
